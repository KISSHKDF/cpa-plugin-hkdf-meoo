# ADR-0002 构建产物不进版本库，构建不可复现，回滚只靠归档字节

- 状态：已采纳
- 日期：2026-10-17（首次实测确认）/ 2026-10-23（成文）
- 相关版本：全部

## 背景

本机对同一棵未改动的源码树连续构建 4 次，产出 **4 个不同的 SHA-256**
（PE 时间戳恒为 0，所以不是时间戳导致的）。这意味着：

1. **构建不可复现** —— 无法通过"重新构建"来验证线上件是否来自某次提交
2. 因此**线上件的唯一身份证据就是它的字节**，一旦丢失就无法重建
3. 把产物提交进版本库会让人误以为"可以随时从源码重建"，掩盖上述事实

## 决策

1. **构建产物一律不进版本库**：`*.dll` / `*.h` / `*.exe` / `build-out/` 全部 `.gitignore`
2. **每次部署前必须归档**：`C:\CLIP\_plugin-archive\<id>\v<版本>\` 内含
   - `<id>-v<版本>.dll`（字节本体）
   - `SHA256SUMS.txt`（哈希）
   - `RELEASE-INFO.txt`（版本、构建时间、sha256、字节数、源码树路径、tree-head）
3. **回滚 = 从归档恢复字节，绝不重新构建**
4. 源码树里**只允许** `build-out/` 存放产物，且 `build-out/` 必须 gitignored

## 被否掉的选项

| 选项 | 为什么否掉 |
|---|---|
| 把产物提交进 git | 仓库膨胀（每版 8-13 MB × 每天多版）；且暗示可重建，误导 |
| 不做归档，需要时重建 | 构建不可复现，重建出的字节与线上件不同，无法证明回滚成功 |
| 用 `-buildvcs=false` + 固定时间戳试图复现 | 已试过，仍不可复现（Go 链接器本身引入非确定性） |

## 后果

- **好的**：回滚有确定的字节依据；`plugin-tree-guard.ps1` 能用"部署件哈希必须能在登记树
  的 `build-out/` 里找到"来证明"这个 DLL 确实出自这棵树"（在用人证）。
- **代价**：磁盘占用（归档当前 968 MB）；归档目录成为**不可丢的资产**，
  清理时必须逐版确认"不是任何在用工件的回滚点"。
- **什么时候该重新考虑**：如果哪天能证明构建可复现（例如换了工具链后实测 10 次同哈希），
  那时可以把产物纳入版本库或改用可重建策略。

## 证据

- 2026-10-17 实测：同一棵树 4 次构建 4 个 SHA-256，PE 时间戳均为 0
- `CONVENTIONS.md` 第四节（发版顺序第 7 步"归档"）
- `plugin-tree-guard.ps1` 第 3 项检查「在用人证」
- `cpa-plugin-updater\gates\release-check.ps1` 的 `release-archived` / `deploy-equals-archive` 检查项
